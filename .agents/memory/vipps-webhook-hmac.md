# Vipps webhook HMAC-SHA256 verification

## The rule
Vipps signs webhooks with HMAC-SHA256 (same as Azure Event Grid), NOT Bearer tokens.
The secret is returned by Vipps when the webhook is registered — never generated by the merchant.

## Authorization header format from Vipps
```
HMAC-SHA256 SignedHeaders=x-ms-date;host;x-ms-content-sha256&Signature=<base64>
```

## String to sign
```
POST\n<requestPathAndQuery>\n<x-ms-date>;<host>;<x-ms-content-sha256>
```
x-ms-content-sha256 = base64(SHA-256(rawBody))
Signature = base64(HMAC-SHA256(key=VIPPS_WEBHOOK_SECRET, data=stringToSign))

## Express raw body requirement
`express.json()` destroys the raw bytes needed for HMAC. In `app.ts`, a conditional
middleware applies `express.raw({ type: () => true })` to the webhook path only:
- Webhook path: `/api/billing/vipps/webhook` → req.body = Buffer
- All other paths: `express.json()` as normal
Route handler calls `verifyVippsWebhookHmac(req, rawBody)` then `parseVippsWebhookEvent(rawBody)`.

## Proxy/Host header
Replit proxy changes the Host header. Use `VIPPS_WEBHOOK_EXPECTED_HOST` env var to
override to the public domain. Falls back to `x-forwarded-host` then `req.hostname`.

**Why:** Bearer token comparison is trivially bypassable with replay attacks. HMAC-SHA256
also verifies the body hasn't been tampered with in transit (content hash check).
