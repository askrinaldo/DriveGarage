Act as a Senior Product Manager, SaaS Architect, UX Lead, Backend Architect and Launch Readiness Reviewer.

Project:
DriveGarage

Goal:
Perform a complete product improvement audit of the entire project and convert the findings into clear Replit tasks.

Do NOT begin implementing everything immediately.

First inspect the full codebase and application experience, then create a prioritized task backlog.

The goal is to make DriveGarage:

- easier to understand
- easier to use
- faster
- cleaner
- more professional
- easier to maintain
- ready for a later security-hardening phase

This review must cover both frontend and backend.

==================================================
SCOPE
==================================================

Review the entire product, including:

- public landing page
- sign-in and sign-up flow
- authenticated layout
- dashboard / Oversikt
- Garasjen min
- vehicle detail pages
- service
- documents
- mileage / driving log
- clubs and club detail
- profile
- subscription and billing
- account deletion
- admin functionality
- navigation
- mobile experience
- empty states
- loading states
- error handling
- API design
- database model
- duplicated or legacy functionality
- unused code
- performance
- maintainability

Do not focus on penetration testing or deep security hardening yet.

Security findings may be recorded, but the primary goal of this phase is product quality, usability and technical cleanup.

==================================================
AUDIT QUESTIONS
==================================================

For every major page and feature, assess:

1. Is the purpose immediately clear?
2. Is anything duplicated?
3. Is anything unnecessary?
4. Is anything confusing?
5. Is anything unfinished?
6. Is anything visually inconsistent?
7. Is any functionality hidden or hard to discover?
8. Are there buttons or links that do not work?
9. Are there empty states that feel dead?
10. Are there long loading times or unnecessary API requests?
11. Are frontend and backend responsibilities cleanly separated?
12. Is there legacy code that should be removed?
13. Are there routes or modules that no longer fit the final product?
14. Could anything be simplified without losing value?
15. Does the mobile experience work naturally?
16. Does the product feel like one coherent application?

==================================================
PRODUCT SIMPLIFICATION
==================================================

Identify anything that should potentially be:

- removed
- hidden
- postponed
- merged
- simplified
- renamed
- moved to a better location

Pay particular attention to:

- duplicated dashboard and garage content
- legacy organization functionality
- gamification
- local support/ticket systems
- chatbot code
- duplicate auth systems
- old Stripe remnants
- unused admin tools
- unfinished features
- unnecessary navigation items
- pages that add maintenance cost without clear user value

Do not remove anything during the audit.

Create a task or recommendation first.

==================================================

Review:

- missing validation

- subscription and billing maintainability
- data ownership and deletion flows
- logging and observability
- technical debt that could block launch

Do not perform destructive database changes.

==================================================
TASK CREATION
==================================================

Create tasks in Replit for all meaningful findings.

Each task must contain:

- clear title
- problem statement
- why it matters
- affected files or areas
- recommended solution
- acceptance criteria
- risk level
- estimated size:
  - XS
  - S
  - M
  - L
  - XL
- category:
  - UX
  - Frontend
  - Backend
  - Performance
  - Cleanup
  - Billing
  - Mobile
  - Accessibility
  - Product
  - Security-later
- priority:
  - P0 blocker
  - P1 high
  - P2 medium
  - P3 low

Group related findings into one task where that creates a cleaner implementation.

Do not create dozens of tiny duplicate tasks.

==================================================
TASK EXECUTION RULES
==================================================

Do not automatically implement large or risky tasks.

For tasks marked L or XL:

- create the task
- explain the recommended approach
- identify dependencies
- wait for approval before implementation

For safe XS or S tasks:

You may suggest that they can be completed directly after the backlog is reviewed.

Do not make changes to main solely because a task is easy.

First create and present the backlog.

==================================================
PRIORITIZATION
==================================================

Prioritize tasks that improve:

1. broken or confusing user flows
2. core product usability
3. page differentiation
4. speed and perceived performance
5. mobile usage
6. maintenance cost
7. code clarity
8. launch readiness

Do not prioritize cosmetic micro-details above broken functionality or confusing architecture.

==================================================
FINAL OUTPUT
==================================================

Return a concise audit report with:

1. Overall product assessment
2. Top 10 highest-value improvements
3. Features that should be removed or postponed
4. Frontend findings
5. Backend findings
6. Performance findings
7. Mobile findings
8. Technical debt
9. Risks before launch
10. Tasks created, grouped by priority
11. Recommended execution order
12. Which tasks are safe to do immediately
13. Which tasks require approval before implementation

End with a clear recommendation:

- what should be done first
- what should be postponed
- when the project is ready to begin the dedicated security-hardening phase
