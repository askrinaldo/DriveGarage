Important confirmed issues from the previous report:

1. The previous report claimed:
   “Vipps Recurring initiates charges automatically after agreement activation.”

This is incorrect.

Official rule:

* Charges are NOT created automatically from an agreement.
* DriveGarage, as merchant, must create every recurring charge.
* Each charge requires a unique orderId and idempotency key.
* Recurring charges should be created according to the official lead-time and due-date rules.

2. The previous report claimed webhook authentication uses:
   `Authorization: Bearer <VIPPS_WEBHOOK_SECRET>`

This is incorrect for the official Webhooks API.

Official webhook verification requires:

* the secret returned by Vipps when the webhook is registered
* raw request body
* `x-ms-date`
* `x-ms-content-sha256`
* `Host`
* `Authorization: HMAC-SHA256 ...`
* SHA-256 content hash validation
* HMAC-SHA256 signature verification over:
  `POST\n<pathAndQuery>\n<date>;<host>;<contentHash>`

Do not generate an arbitrary bearer-token webhook secret and treat that as secure verification.
